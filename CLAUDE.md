# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal site for Burlibu, published at https://burlibu.github.io. Create React App (`react-scripts` 5) + React 19 + Tailwind CSS 3 + react-three-fiber. UI text is in Italian.

## Commands

- `npm start` — dev server
- `npm run build` — production build into `build/`
- `npm run deploy` — manual deploy via `gh-pages` (normally not needed, see below)

There's no lint script. ESLint runs inside `react-scripts` (`react-app` config) during start and build. CI sets `CI=true`, which turns any ESLint warning into a build error and blocks the deploy, so run `CI=true npm run build` before pushing.

There's no test setup: there is no `test` script, and CRA's Jest 27 can't resolve react-router 7's package exports. Verify changes with screenshots: `node scripts/shot.js <target> [WxH] [out.jpg]` serves the page itself, finds Chrome (or `$CHROME`) and prints the path of a half-scale JPEG (~70 KB). Read that file rather than full-size PNGs. `designs/<name>/index.html?…` targets load from `public/` with no build, while route targets (`resources`, `""` for home) load from `build/`. Write routes without `#/`, because Git Bash rewrites `#/x` into a Windows path. The home page never finishes a headless screenshot, so the script gives up after `--timeout=90` seconds. Check a tile by shooting its design with `?preview` instead. `--wait=ms` sets the virtual time budget and `--scale=1` saves full resolution.

Responsive check: `npm run check:responsive` builds, then runs `scripts/responsive-test.html` in headless Chrome. The page loads every route in same-origin iframes at 8 viewports (360px phone to 2560px) and reports horizontal scroll, tiles that overflow, clipped labels and back-link placement. The script prints only the FAIL lines and a count, and exits 1 on failure. It also fails if a `<Route>` in `src/App.js` is missing from `ROUTES` in the test page. Use `node scripts/check-responsive.js` to skip the build. Headless WebGL screenshots of `/graph3d` can show stale frames, so check the 3D camera by reading its state rather than trusting the screenshot.

## Deployment

Every push to `main` triggers `.github/workflows/deploy-gh-pages.yml`, which builds with Node 18 and publishes `build/` via `peaceiris/actions-gh-pages`. A second workflow (`setup-react-tailwind.yml`) rebuilds and checks that `src/index.css` still contains the three `@tailwind` directives. Don't remove them.

## Architecture

- The home page (`/`) is a 3×3 bento grid in `src/App.js`. Each tile links to one section. The `tiles` array holds `[col, row, route, label, preview]`, and the center piece is rendered separately. A tile with no route is a "Prossimo design" placeholder slot. Once the 3×3 is full, new tiles go in the `more` array, rendered as plain 3-column rows (`.bento-more`) below the bento that the page scrolls down to.
- The hover grow effect is pure CSS in `src/index.css`: `.bento:has([data-col|data-row]:hover)` swaps the `fr` tracks and transitions them. It's a no-JS port of the GSAP Flip demo in `inspiration/flilp-bento-hover-effect`. At 900px and below the grid becomes a plain 2-column stack.
- Standalone vanilla designs live in `public/designs/<name>/index.html`, copied from `inspiration/`. `DesignFrame` shows one full screen in an iframe. The tile shows a live preview iframe rendered at 4x and scaled to 0.25.
- Tile previews load the design with `?preview`. Each design includes `public/designs/preview.js` before its own script. In preview mode that script quarters `devicePixelRatio`, debounces `resize` listeners (so a tile's hover grow doesn't rebuild the scene every frame), and holds `requestAnimationFrame` while the tile is off-screen. Size canvases from `devicePixelRatio` and set them up in a `resize` listener so they benefit from this.
- Avoid per-frame style recalc over many elements in a design, such as animating an inherited custom property that hundreds of nodes read. That's what made the home lag. Animate a transform on a container instead.
- To add a design: copy it to `public/designs/<name>/`, add `<script src="../preview.js"></script>` before its scripts, add a `<Route>`, and replace a placeholder tile (or add one to `more`).
- `src/Graph3D.js` (`/graph3d`) is a react-three-fiber knowledge-base graph in the style of Obsidian. It loads lazily because three.js is about 1 MB. Its notes are dummy data generated deterministically in `src/knowledge.js`, about 100 of them with links and backlinks. Each node opens `/graph3d/nodo/<slug>`, which `src/NotePage.js` renders. The layout is a 3D force simulation computed once and scaled to `GRAPH_RADIUS`. The background (particles, wave grid, frequency lines) is drawn in shaders.
- `src/Resources.js` (`/resources`) is a scrollable page of curated web design links, styled as a technical drawing sheet after `inspiration/technicalchart`. The links live in `src/resourcesData.js`. Each card takes the next pen colour and the next of 8 frame styles, so neighbouring cards never match. The filter morphs with the View Transitions API.
- `src/Fcq.js` (`/fcq`, lazy) is "Fondamenti di Computazione Quantistica", four interactive plates built from the course notes (Drive folder `Fcq`, cap. 2-4): superposition and measurement, the Bloch sphere (react-three-fiber, `frameloop="demand"`, paused off-screen), gates as Bloch rotations, and a two-qubit composer with Bell states. `src/qmath.js` is the DOM-free state-vector maths (gates, measurement, concurrence, LaTeX kets); formulas render with KaTeX. It uses the standard convention (|0> at the north pole), while the notes put |1> there, and a note on plate B says so. Its styles are scoped under `.qc-desk`/`qc-` in `src/fcq.css`. Its tweens run on `requestAnimationFrame`, which doesn't fire under headless `--virtual-time-budget`, so test its interactions in real time.
- Tiles without a design iframe have a React face in `src/TileFaces.js`: `ContactFace` (airmail envelope), `GithubFace` (contribution calendar, branches, terminal), `ResourcesFace` (a mini drawing sheet) and `GraphFace` (the real knowledge graph on a 2D canvas, paused off-screen) and `QuantumFace` (a precessing Bloch vector in SMIL). Faces size their contents with container query units (`cqmin`). Those units resolve against the nearest ancestor container, not the element itself.
- `public/designs/dash` (Prisma Dash) is a Geometry Dash-style game. `game.js` is the DOM-free engine: levels, fixed 240 Hz physics and collisions. `script.js` handles rendering (sprites cached per block size, interpolated between physics steps), the WebAudio music, input and screens. `node scripts/dash-solver.js [level]` runs a beam search proving every level can be finished with all coins, and rewrites `demos.js` (the winning inputs replayed by the demo, menu background and tile preview). Rerun it after any change to a level or to the physics, or the demos will crash. `?livello=N&demo` opens a level's demo directly. Headless Chrome only renders a few frames of the game, so to screenshot later parts, step the simulation forward in a throwaway copy.
- `public/designs/acquerello` (Erbario) is a watercolor-on-paper landing section. `paint.js` paints procedural watercolor into canvases: washes are deformed polygons stacked as ~30 translucent multiply layers, plus blooms, dried stains, splatter, brush strokes and leaves. `script.js` maps each `canvas.paint[data-p]` to a painter, paints it once when it nears the viewport and again only when its size changes, draws the pencil outlines around `.sketch` boxes, and masks the photo with a wet edge. `mockup.html` is the desktop + mobile overview: the live page in device frames (`?bare` hides the overview button).
- `public/designs/vault` (Vault) is a 36-month personal finance minigame in a dark bento-grid style. `game.js` is the DOM-free engine (seeded markets with calm/bull/bear regimes, random and choice events, delayed outcomes, debt, score) and can be required from node to simulate strategies when retuning numbers. `script.js` renders it: the chart canvas, the monthly plan sliders, toggles and autopilot (on `requestAnimationFrame`). `?seed=N` fixes the game; in `?preview` the autopilot plays itself and restarts.
- `public/designs/stelle` (Stelle Erranti) is a short elemental adventure in a gold-framed celestial fantasy style. `game.js` is the DOM-free engine: three seeded star-map regions, turn-based battles with elemental auras and reactions, events, wishes with rarity and pity, and an `auto()` player that drives the tile preview and node simulations. `script.js` renders the map (vertical below 720px), the side panels and the modal screens. `?seed=N` fixes the run, `?tema=pergamena` opens the light parchment theme.
- `public/designs/blasone` (Blasone) is an original card game in a heraldic woodcut editorial style: six simultaneous turns over the four quarters of a shield, each quarter with a field rule and crowns, beasts with static abilities and a metal/colour tincture law. `game.js` is the DOM-free engine; `evaluate()` recomputes every power from the board, and `choose()` is the AI (it also plays your side in `?preview`). `script.js` engraves each beast at load by redrawing its emoji on a canvas as woodcut hatching, so the art depends on the system emoji font. Tinctures are shown with Petra Sancta hatching patterns defined in `index.html`.
- `public/designs/ardesia` (Ardesia) is a chess game on a slate, walnut and amber table. `game.js` is the DOM-free engine: full rules on a 0x88 board, FEN in and out, SAN and PGN, and an alpha-beta AI with three levels (depth 1, 3 and 4). After touching move generation, check it against the standard perft counts (`new Chess(fen).perft(d)` in node). `ai.js` runs the search in a worker. `script.js` draws the board as 64 buttons with inline SVG pieces and handles clicks, pointer drag, the keyboard, promotion, clocks, undo/redo and export. `?fen=` sets the starting position, `?seed=N` fixes the AI, and in `?preview` two AIs play each other. Headless `--virtual-time-budget` doesn't wait for the worker, so a test harness must block on real time (for example with sync XHRs) before checking an AI reply.
- Routing uses `HashRouter` (URLs look like `/#/wind`) because GitHub Pages has no SPA fallback.
- Styling uses Tailwind utilities plus the bento/frame classes in `src/index.css`. The service worker is `unregister()`ed in `src/index.js`.
